# По шагам

Планер задач на FastAPI с интерфейсом на русском языке. PostgreSQL хранит задачи
и шаги, Kafka передаёт запросы обработчику, YandexGPT составляет план.
Фронтенд включён в образ API и доступен по `/`; отдельная сборка Node.js не нужна.

## Запуск

```powershell
Copy-Item .env.example .env
# Заполните YANDEX_CLOUD_API_KEY и YANDEX_CLOUD_FOLDER
docker compose up --build -d
```

Интерфейс: http://localhost:8008. Swagger UI: http://localhost:8008/docs.
Для CRUD без генератора: `docker compose up --build -d app kafka-init`.
Compose запускает PostgreSQL и Kafka, создаёт топик. API создаёт таблицы при старте.

## Возможности

- Создание, редактирование, удаление и завершение задач.
- Поиск по названию и описанию, фильтры состояния и счётчики.
- Просмотр плана, отметка шагов и прогресс выполнения.
- Повторный запрос генерации, если план не появился.
- Обновление списка для незавершённых задач без плана каждые 5 секунд.
- Адаптивная вёрстка, управление с клавиатуры, сообщения об ошибках.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET/POST | /todos | Список и создание |
| GET/PUT/DELETE | /todos/{id} | Просмотр, изменение, удаление |
| POST | /todos/{id}/generate | Запрос плана: 202 при отправке, 503 при сбое Kafka |
| PATCH | /todos/{id}/steps/{step_id} | Изменение completed шага |
| GET | /health | Проверка API-процесса |
| GET | /metrics | Метрики Prometheus |

Тело POST/PUT задачи:

```json
{"title": "Выучить Python", "description": "Практика каждый день", "completed": false}
```

## Генерация и ошибки

Задача сначала сохраняется в БД, затем запрос отправляется напрямую в Kafka
с ожиданием подтверждения. Сбой отправки журналируется и не отменяет сохранение.
Автоматической гарантированной доставки после сбоя отправки нет: повторите запрос
кнопкой «Составить план». Outbox удалён из приложения и Compose. Старая таблица
`outbox_events`, если она есть, больше не используется; приложение её не удаляет.

Обработчик подтверждает offset после сохранения шагов. При ошибке БД или LLM
сообщение повторяется. Блокировка задачи предотвращает дублирование шагов.
Некорректные события журналируются и пропускаются. Постоянная ошибка блокирует
свою партицию до устранения причины; очереди ошибок пока нет.
При редактировании задачи существующий план сохраняется.
Генерация требует работающего worker и настроек Yandex Cloud.

## Kubernetes и CI

Чарт: `CSU-2026-2/demo-app-helm` (локально `../demo-app-helm`). Он разворачивает
API с фронтендом, worker, Service и опциональный Ingress. PostgreSQL, Kafka,
TLS и секреты предоставляет окружение. Workflows обновляют адреса и теги образов,
используют отдельные кеши Docker и учитывают изменения `common/**`.

## Проверки

```powershell
docker build -f tests/Dockerfile -t demo-app-tests .
docker run --rm demo-app-tests
```

По умолчанию тесты используют SQLite и подменённые Kafka/LLM. Для PostgreSQL
задайте контейнеру `TEST_DATABASE_URL` отдельной тестовой БД: тесты создают
и удаляют таблицы. Проверка параллельной обработки выполняется только на PostgreSQL.
